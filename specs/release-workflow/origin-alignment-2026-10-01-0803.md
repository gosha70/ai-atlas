Origin claim:
> Epic #23 Phase 5 §10, issue #58: record what was published as immutable snapshots under .atlas/releases/<version>/, derive a changelog from the Contract IR, and police what may leave the contract between publications with a deprecation policy. The owner-settled draft (3806e5d, "No owner decision remains open") supersedes the spike prototype: credit only from proved local git tags (tagName, default v{version}), a processor-written contract-resources.json manifest with reserved-path stale-file rejection, channel-aware removal credit using the gate's shared reachability, a git-free agenticReleaseHistoryCheck under check and a git-aware agenticReleaseVerify. The owner decided to expand PR #62 to this full scope before merge, and the three review findings on bb98010 must be closed.

Working claim:
> `agenticRelease` snapshots the accepted contract to an immutable, atomically written `.atlas/releases/<version>/` (IR, OpenAPI, MCP tools, diff, changelog section, `release.json` with digests, `tagName` and the embedded contract-resources manifest), validating the class output as found against the processor-written `contract-resources.json` with no task dependency that could regenerate it, and rejecting rather than repairing stale or missing reserved resources (an empty module gets a fresh canonical empty contract on the compile path only). Deprecation credit comes only from published releases whose `tagName` tag, read through a read-only, offline, environment-isolated git CLI, peels to an ancestor of HEAD and holds a byte-identical snapshot; only the newest snapshot may be pending; shallow clones, orphan tags and untagged older snapshots fail. Removal credit is channel-aware via the gate's reachability. `agenticReleaseHistoryCheck` (under `check`, git-free) verifies digests, the `previous` chain and the aggregate changelog; `agenticReleaseVerify` (outside `check`) requires the tag at HEAD and compares IR canonically, artifacts byte for byte and configuration structurally. The release machinery runs in the plugin's isolated worker against the processor's comparison/policy API. AC1–AC20 and draft items 1–10 each map to code and tests, and the three bb98010 findings are closed with regressions.

Mismatches:

Added for a concrete failure (Git for Windows `core.autocrlf` would rewrite released bytes and break every digest and tag proof), raised in Phase E review; not yet recorded as an owner decision in `spec.md`.
  - The effective configuration in `contract-resources.json` records `ai.atlas.collections` as a sixth option, beyond the five the draft lists, because it changes the IR, OpenAPI and MCP schemas; not yet recorded as an owner decision.
  - For a module with no ai-atlas declarations, the empty contract is written in `compileJava.doLast`, so a processor version mismatch is reported by `compileJava` rather than `atlasContractCheck`; consequence of the OQ-2 decision (plugin produces the empty contract when javac does not run the processor), not separately recorded.
  - Non-blocking: the "another processor's resources are ignored" case is tested by simulating a foreign `META-INF/` file, not by running a second annotation processor; issue #58's body still links the superseded draft `d15fe77` (spec.md records the supersession).
